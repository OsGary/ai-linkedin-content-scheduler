# App Flow Document for AI LinkedIn Content Scheduler

## Onboarding and Sign-In/Sign-Up

A new user first arrives at the landing page by typing the app URL or clicking a shared link. The landing page highlights key features of the AI content scheduler and includes a prominent button that leads to the sign-up page. On the sign-up page, the user enters their name, email address, and a secure password. After clicking the sign-up button, the user receives a brief confirmation message before being taken to the next step. If the user already has an account, they can instead follow a link to the sign-in page where they enter their email and password to log in. In the event of forgotten credentials, a "Forgot Password" link on the sign-in page allows the user to input their email address and receive a password reset link. Clicking the link in the email brings them back to the app with a form to create a new password. After successfully signing in or signing up, the user is automatically redirected to the initial dashboard view. To sign out, the user clicks on their profile avatar in the header and selects "Sign Out," which immediately ends the session and returns them to the landing page. 

## Main Dashboard or Home Page

Upon logging in, the user lands on the dashboard located at `/dashboard`. The page header displays the app logo on the left, a theme toggle in the center, and the user avatar with a dropdown menu on the right. A vertical sidebar along the left edge contains navigation links labeled Dashboard, Create Post, and Settings. In the main content area, four horizontal columns form a swimlane view for post statuses: Idea, Draft, Scheduled, and Published. Each column holds post cards that show the title, snippet of content, and scheduled time if applicable. At the top of each column header there is a count of the cards in that column. Above the swimlane, a toolbar offers a "New Post" button and a mini calendar widget that highlights days with scheduled posts. Selecting any item in the sidebar instantly transitions the main area to preview the corresponding page, while keeping the header and sidebar in place for consistent navigation.

## Detailed Feature Flows and Page Transitions

When the user wants to create new content, they click the "New Post" button in the toolbar. A full-screen modal appears with two tabs: "AI Generate" and "Manual Draft." In the AI Generate tab, the user types a brief instruction or topic and clicks "Generate." A loading spinner displays while the AI client in `lib/openai.ts` fetches variations. Once ready, a list of suggestions appears. The user selects a variation, which populates a rich text editor where they can further edit content. They then choose either "Save as Draft" or "Schedule Post." "Save as Draft" closes the modal and places the card in the Draft column. "Schedule Post" reveals a date and time picker inline. After selecting a date and time and confirming, the modal closes and the card appears in the Scheduled column. In the Manual Draft tab, the user can type directly into the editor and then follow the same steps to save or schedule. 

To adjust an existing post, the user clicks its card in any column. This navigates to `/dashboard/post/[id]`, a detailed page showing the full content editor and a sidebar panel for scheduling settings. The user can edit text, change status by selecting a new column from a dropdown, or update the scheduled date. Clicking "Save Changes" triggers an API call to `/api/posts/route.ts` and then returns the user to the dashboard, where the swimlane view refreshes. 

Organizing content between stages is done by dragging a card to a different column. As the card moves, the UI shows a guide line and on drop, a background request updates the post status. If successful, the card stays in the new column; if it fails, it returns to its original place with an error toast explaining the issue. 

To connect a LinkedIn account, the user navigates to Settings and selects the LinkedIn section. A "Connect to LinkedIn" button redirects to the OAuth consent screen. After granting access, LinkedIn redirects back to `app/api/auth/linkedin/route.ts`. The server stores the access and refresh tokens in the `linkedinAccounts` table and then sends the user back to the Settings page with a success banner. If anything goes wrong, an error message appears with guidance to retry. 

Publishing happens automatically through a Vercel Cron Job that calls `/api/cron/publish/route.ts` every five minutes. This endpoint queries the database for posts where the scheduled time has passed and status is Scheduled. For each post, the server uses the `lib/linkedin.ts` client to send the content to LinkedIn. Upon success, the post status updates to Published, and the card moves to the Published column on the next dashboard refresh.

## Settings and Account Management

In the Settings section, the user sees multiple tabs for Profile, AI Preferences, Notifications, and LinkedIn. In Profile, they can update their name or email and change their password by entering the current and new passwords. AI Preferences lets them define their default tone of voice or system prompt examples used for content generation. Notifications allow toggling email alerts for successful post publishing or errors. The LinkedIn tab displays account connection status and offers a "Disconnect" button that revokes tokens and removes them from the database. Any changes in Settings are saved via an API call and confirmed with an on-screen message. From Settings, the user returns to the dashboard by clicking the Dashboard link in the sidebar or the app logo in the header. 

## Error States and Alternate Paths

If the user enters invalid data anywhere—such as a wrong email format, too short a password, or an empty AI prompt—the form highlights the offending field and displays a concise inline message. During the OAuth flow, if LinkedIn denies access, the app shows a clear explanation and a button to retry connecting. When scheduling or saving a draft, if the server is unreachable or returns an error, the modal remains open with an error banner, and the user can correct the issue or cancel. While dragging cards, if network connectivity is lost mid-drag, a toast warns the user and the card animates back. For forgotten passwords, if the reset token is expired, the reset page shows a prompt to request a new link. Throughout the app, a global banner appears at the top if the network check fails, allowing users to know their offline state and disabling features that require a live connection. 

## Conclusion and Overall App Journey

In a typical session, a user lands on the marketing page, signs up or logs in, and arrives at their dashboard. They immediately see their swimlane of posts and can connect their LinkedIn account from Settings. Creating new posts is effortless using AI generation or a manual editor, and scheduling is done in the same flow. Drag-and-drop organization moves content through the stages until it reaches Scheduled. Behind the scenes, a cron job publishes posts automatically to LinkedIn and updates the status to Published. The user can tweak personal details, adjust AI tone, and manage notification preferences in Settings, always returning easily to the core dashboard to continue creating and scheduling successful LinkedIn content.
